# 分类规则

## 分类清单（7 类 + 其他兜底）

| 枚举值 | 中文 | 典型例子 |
|---|---|---|
| `DINING` | 餐饮 | 饭店、外卖、聚餐 |
| `TRANSPORT` | 交通 | 打车、公交、地铁、火车票、机票 |
| `SHOPPING` | 购物 | 网购、日用品、服装 |
| `OFFICE` | 办公 | 办公用品、打印、文具、买书/教材、**办公耗材** |
| `RESEARCH` | 科研 | 试剂、**实验室耗材**、实验设备、论文版面费/润色 |
| `LODGING` | 住宿 | 酒店、宾馆 |
| `CONFERENCE` | 会议培训 | 会议注册费、培训费 |
| `OTHER` | 其他 | 兜底（识别不出或不在以上类别） |

---

## 边界规则（钉死，AI 不乱分）

### 1. 耗材按「谁用」区分
- **实验室用** → `RESEARCH`（科研）
- **办公室用** → `OFFICE`（办公）

### 2. 论文相关
- **论文版面费 / 润色** → `RESEARCH`（科研产出成本）
- **买书 / 教材** → `OFFICE`（学习办公用品）

### 3. 出差拆分（不设"差旅"混合类）
- 火车票 / 机票 / 打车 → `TRANSPORT`（交通）
- 酒店 / 宾馆 → `LODGING`（住宿）
- 统计时「交通 + 住宿」加起来即差旅总额

---

## 重要概念：OTHER 是「正常桶」，不是「识别失败」

- 识别成功与否由 `isInvoice` 和字段完整度决定，**与分类无关**。
- 一张真发票若不属于 7 类中的任何一类，会归入 `OTHER`——这是分类体系的必然结果，不是 AI 出错。
- 只有「不是发票」（`isInvoice=false`）才会标记为 `NOT_INVOICE`（不可信）。
- 若某天 `OTHER` 占比异常高，说明分类还不够覆盖真实场景，是**产品信号**（提示要扩分类），而非 bug。

---

## 为什么不继续细分

- 类别越多，AI 犹豫的边界越多，正确率下降。7 类在「覆盖报销场景」和「识别准确率」之间取了平衡。
- 刻意不设 `BOOK`（书籍）类：买书归 `OFFICE`、版面费归 `RESEARCH`，避免"书"和"办公/科研"边界打架。
